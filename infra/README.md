# Azure infrastructure (M4)

The same Helm chart that CI tests in kind, deployed to AKS. Terraform provisions it and a GitHub Actions
workflow drives it: `plan` on PR → approval → `apply` → deploy → test → (evaluation) → `destroy`.

```
infra/terraform/
  bootstrap/   one-off, run locally by the subscription owner: Terraform state storage, two GitHub OIDC identities,
               budget alert. Lives for the whole project.
  env/         the environment, created and destroyed many times: AKS, ACR, Key Vault, workload identity.
```

## What `env/` creates

| resource | why |
|---|---|
| AKS, 1 node, Free control plane | the chart from `deploy/helm/raglab` with `values-azure.yaml` |
| Azure CNI overlay + Cilium | enforces the chart's NetworkPolicies (Postgres and LiteLLM reachable only from the release) |
| Entra ID + Azure RBAC on the cluster, local admin account disabled | no static kubeconfig credentials; the workflow gets cluster-admin through its identity |
| app routing add-on (managed NGINX ingress) | public API endpoint; `/ask/stream` without buffering |
| ACR Basic, admin user off | the API image, built with `az acr build`; the kubelet pulls with `AcrPull` |
| Key Vault (RBAC) + Secrets Store CSI driver | Postgres password, LiteLLM master key and the demo key are generated by Terraform, and the model gateway key comes from the GitHub environment secret. Pods read all of them through **workload identity**. No secret is in the repo, in values or in the image |
| user-assigned identity federated with the cluster OIDC issuer | `system:serviceaccount:raglab:raglab` → `Key Vault Secrets User` |

Models are not on Azure. The LiteLLM pod reaches the model gateway through a **WireGuard tunnel**: a
[wireproxy](https://github.com/windtf/wireproxy) sidecar runs WireGuard in user space, with no `NET_ADMIN` and no
kernel module, and exposes the gateway on `127.0.0.1:8317` inside the pod. The tunnel peer is filtered on the
WireGuard hub, where it may reach one address and port (the model gateway) and nothing else in the VPN. Nothing is
published to the internet for this. Swapping the model provider is one line of LiteLLM config. A free-trial subscription only gets quota for older Azure OpenAI models, and the demo
already uses a stronger one.

## Security model of the workflow

- **Two identities.** `plan` runs on pull requests with a read-only identity (Reader, state blob reader) and
  `-lock=false`. PR code cannot change anything on Azure.
- **Writes only from the `azure` environment.** The write identity's federated credential is bound to
  `repo:<owner>/<repo>:environment:azure`, and that environment requires a reviewer. `apply`, `destroy` and
  deployments wait for approval.
- **Bounded role delegation.** The write identity is Contributor plus *Role Based Access Control Administrator*,
  but with an ABAC condition that allows assigning only AcrPull/AcrPush, Key Vault Secrets User/Officer and AKS RBAC
  Cluster Admin. It cannot make anything Owner.
- **State.** Kept in an Azure Storage blob with versioning, Entra ID auth only (shared keys disabled), and lease
  locking.

## Region

The environment runs in **Sweden Central**. On the free-trial subscription, Poland Central blocks every small VM size
(B, D, F families all return `NotAvailableForSubscription`; only large FX and GPU sizes are open), while Sweden
Central offers them. Checked with `Microsoft.Compute/skus` before writing any code. The Terraform state account
lives there too.

## First-time setup (owner)

```bash
az login
cd infra/terraform/bootstrap
terraform init
terraform apply -var subscription_id=$(az account show --query id -o tsv) -var alert_email=<you@example.com>
terraform output github_variables     # → GitHub: Settings → Secrets and variables → Actions → Variables
```

Then in GitHub:
1. **Variables**: `AZURE_CLIENT_ID`, `AZURE_PLAN_CLIENT_ID`, `AZURE_TENANT_ID`, `AZURE_SUBSCRIPTION_ID`,
   `TFSTATE_RESOURCE_GROUP`, `TFSTATE_STORAGE_ACCOUNT`, `TFSTATE_CONTAINER`.
2. **Environment `azure`** with *Required reviewers* and deployments from `main` only, plus secrets `LLM_API_KEY`
   (model gateway key) and `WIREGUARD_CONF` (the tunnel peer's wireproxy config).
3. Actions → *azure* → *Run workflow* (`apply`, optionally `run_eval`, `destroy_after`).
